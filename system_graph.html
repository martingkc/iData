File Upload → MongoDB

every 60 s

file_parser_thread

Background thread polls MongoDB via FileFetcher. Picks up documents where parsed=false OR updated=true. Runs continuously; one document at a time.

async thread document_parser_backend · Port 5000
3

DocumentParser.parse_to_md()

Converts PDF to Markdown using Docling.

  • Extracts inline images → OCR text merged with surrounding content
  • Detects and removes repeating headers / footers (heuristic)
  • Returns (parsed_markdown, dl_doc) — dl_doc keeps structure for chunking
Docling PDF pipeline OCR enabled
4

build_doc_context_llm()

Sends first ≤3 000 chars of Markdown to an LLM. Returns a single-sentence summary (≤300 chars) describing the document's content. This context is:

  • Prepended to every chunk's bm25_text to improve keyword matching
  • Stored separately in the document catalogue for discovery-phase search
LLM summarisation max 300 chars output
5

hierarchical_chunking(dl_doc)

Uses docling_core HybridChunker — respects headings, lists, and table boundaries.

  • max_tokens: 512  ·  min_tokens: 80
  • Text chunks — paragraph/section content
  • Table chunks — table text kept in BM25 field only, stripped from dense embedding to avoid noise
  • Each chunk gets: document_id, chunk_index, chunk_type, bm25_text, original_text, context, pages, image_ids
HybridChunker structure-aware LangChain Document objects

How the ResearchAgent retrieves evidence for a user query

User Query

"What does the Q3 revenue report say about APAC?"

Stage 1 — discovery

document_catalogue_search_tool

Hybrid search over document-level summaries in Milvus document_catalogue. Returns top-k document IDs + paths. Identifies which documents are likely relevant before loading any chunks.

BM25 + dense k=5 default
Stage 2 — chunk retrieval

chunk_retriever_tool

Searches document_chunks in Milvus with an optional filter_expr to scope to discovered document IDs.

  • Dense score weight: 0.7
  • Sparse (BM25) weight: 0.3
  • FlashRank BERT reranker applied after retrieval
  • Example filter: document_id == "abc123"
  • Supports page range, chunk type, path filters
k=10 default reranked
if chunks insufficient

retrieve_full_content_tool (optional fallback)

Loads the complete parsed Markdown for a document directly from MongoDB when chunk results are insufficient. Used for deep-dive questions that span the whole document.

MongoDB full parsed_markdown
synthesis

OrchestratorAgent → Response with Citations

Synthesises retrieved chunks + full content into a final answer. Source references include document_id + chunk_index for traceability.

Example Milvus Filter Expressions
Filter by document
document_id == "507f1f77bcf86cd799439011"
Filter tables only
chunk_type == "table"
Filter by page range
pages[0] >= 5 and pages[0] <= 20
Filter by path
local_path like "%Revenue%"
